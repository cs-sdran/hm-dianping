日期：2026-10-24。范围：补齐关注动态接口、验证签到、抽取通用缓存工具并完成后端联调。Redis Stream/消息队列继续按原学习安排暂缓。

## 本次完成的修改

### 关注动态接口

新增 `GET /blog/of/follow?lastId=<时间戳>&offset=0`，调用已有的 `queryBlogOfFollow`。`lastId` 必填，`offset` 默认 0。

第一次查询传客户端当前毫秒时间戳。下一页使用上一次响应 `data.minTime` 作为 `lastId`，使用 `data.offset` 作为 `offset`，两者必须一起更新。响应中的 `data.list` 为笔记列表。每页读取两条 Redis 记录，按时间倒序返回。

已删除的笔记会被跳过，但仍参与游标计算。因此，如果页面列表为空但游标已变化，应继续用新游标查询；列表为空且游标没有变化才表示没有更多 Redis 记录。相同时间戳跨页时累计 offset，避免重复或漏读。

补充了参数缺失和类型错误的处理：返回 HTTP 400 和明确的失败结果，不再误报成服务器异常；负数分页参数仍由业务方法返回失败结果。

### Bitmap 签到

保留用户自己写的签到和位运算统计逻辑。使用可注入的 `Clock`，生产默认北京时间 `Asia/Shanghai`；单测固定时间验证月末、闰年和跨月边界。

接口为 `POST /user/sign`、`GET /user/sign/count`。统计口径是本月截至今天连续签到天数，不跨月；今天未签到返回 0。Redis key 保留现有格式 `sign:<用户ID>:yyyyMM:`，避免改变已写入记录的名字。

### 通用缓存工具

新增 `CacheClient`，将原来放在 `ShopServiceImpl` 中的重复缓存逻辑抽取为可复用方法：

| 方法 | 用途 |
| --- | --- |
| `set` | 普通 JSON 缓存和物理 TTL |
| `setWithLogicalExpire` | 数据和逻辑过期时间一起保存 |
| `queryWithPassThrough` | 缓存命中直接返回，不存在的数据写短期空值 |
| `queryWithMutex` | 冷缓存通过互斥锁保护重建 |
| `queryWithLogicalExpire` | 冷缓存同步加载，过期缓存返回旧值并异步重建 |

数据库查询通过 `Function` 参数传入，工具不依赖商户 Mapper。互斥锁使用随机 token，Lua 校验 token 后删除锁；等待重建有次数上限。重建线程池随 Spring Bean 关闭。

商户详情已实际接入工具，商户更新继续先更新数据库再删除缓存；GEO 查询和索引失效逻辑保留。详情查询及预热使用 `baseMapper.selectById`。登录查询改用字符串列名的 QueryWrapper，规避当前旧版 MyBatis-Plus 在 JDK 17 下使用 Lambda 查询可能遇到的反射兼容问题。
