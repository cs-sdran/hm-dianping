# UV 统计学习说明

本部分按黑马点评实战篇的 HyperLogLog 实验完成，代码位于 `src/test/java/com/hmdp/HyperLogLogUvTest.java`。内容包括访客去重、按天区分统计、空记录以及一百万访客的批量写入实验。当前是可重复运行的学习实验，没有接入网站真实请求，因此运行网站本身不会自动记录 UV。

## 如何运行

在 IDEA 中打开 `HyperLogLogUvTest`，点击类旁的绿色运行按钮可运行全部四项实验。先运行 `testUv`，看懂之后再运行百万访客实验。

测试自动启动和关闭独立的临时 Redis，不需要启动 Spring Boot 或 MySQL，也不会连接开发环境 Redis。启动工具默认使用本机 `D:/Redis/Redis-x64-3.2.100/redis-server.exe`；换机器时可以通过 JVM 参数 `hmdp.test.redis.executable` 指定 Redis 可执行文件。测试日志和临时 Redis 文件位于 `target`。

## 先读 testUv

1. `key` 是统计记录的名字，本实验使用 `test:uv:java:1`。
2. `opsForHyperLogLog().add` 对应 Redis 的 PFADD，用来记录访客标识。
3. `opsForHyperLogLog().size` 对应 PFCOUNT，用来查询去重后的近似人数。
4. 记录 A、B、C 后人数为 3；重复记录 A 仍为 3；再记录 D 后变为 4。
5. `assertEquals` 检查结果是否符合预期；不符合时测试失败。`add` 的返回值不能当作 UV 人数。

UV 指独立访客数，同一个访客重复访问不重复计数；PV 指访问次数，同一个访客访问多次也会累计。

## 按天统计

`differentDaysUseDifferentKeys` 使用两个不同日期的 key，例如 `test:uv:daily:20261024` 和 `test:uv:daily:20261025`。同一个人在一天内只统计一次，第二天来访则计入第二天的 UV。

以后接入业务时，先明确统计整个网站还是某个页面，再把日期和必要的页面标识放入 key。登录访客可以使用稳定的用户 ID；匿名访客需要约定稳定的访客标识。不能在每次请求时重新生成随机标识，否则会把同一个人当作不同访客。日期应按统一的业务时区确定。

## 百万访客实验

`oneMillionVisitorsAreWrittenInBatches` 依次生成 `user_0` 到 `user_999999`，放进长度为 1000 的数组。数组填满后一次提交，共提交 1000 批。这里总数恰好是批大小的整数倍；以后改成其他总数时，需要补充提交最后不足一批的数据。

`i % batchSize` 计算数组中的位置，`(i + 1) % batchSize == 0` 判断当前一批是否已经填满。重复使用这个数组，可以避免同时保留一百万个访客字符串。

HyperLogLog 返回近似计数，不能要求结果严格等于一百万，也不能用它列出访客名单或可靠判断某个指定用户是否来过。需要保存具体访客或精确人数时，应另选合适的存储方式。

## 本次验证结果

2026-10-24 使用真实临时 Redis 验证，4 项测试通过，失败和错误均为 0。

| 场景 | 结果 |
| --- | --- |
| 依次添加 A/B/C、重复 A、添加 D | 3 → 3 → 4 |
| 没有访问记录 | 0 |
| 不同日期分别记录访客 | 分别为 2 和 1 |
| 一百万个不同访客 | 估算 997,461，误差 0.2539% |
| 再提交百万实验的最后一批访客 | 估算人数不变 |

百万实验的 3% 断言阈值只用于本实验的回归检查，不是算法对所有输入的误差保证。本页记录 UV 实验阶段的结果；后续已完成包含 UV 的全量回归，见《实战篇收尾验收报告-2026-10-24》。
