# 库存初始化测试报告

日期：2026-10-17。

## 改动

`VoucherServiceImpl.addSeckillVoucher` 现在会在保存之前拒绝空库存或负库存，任意一次保存返回 false 都立即抛出异常。两次保存成功后注册 afterCommit 回调，数据库提交后才初始化 Redis。初始化返回 false 会抛出“库存初始化未完成”，避免接口误报发布成功。

回调使用保存时捕获的优惠券 ID 和库存值。

### 事务时序与错误处理（新增 10 项）

通过真实 Spring 事务代理、DataSourceTransactionManager 和 TransactionTemplate 驱动事务；数据库 Connection、Mapper、秒杀信息服务和 Redis 资格服务使用 Mockito 模拟。

| 场景 | 验证结果 |
| --- | --- |
| 加入外层事务，两次保存成功 | 提交前不调用 Redis；commit 之后调用初始化一次，传入正确的优惠券 ID 和库存 |
| 两次保存成功，但外层事务最终回滚 | 调用 rollback，不调用 Redis 初始化 |
| 第一次保存返回 false | 立即报错，不执行第二次保存，调用 rollback |
| 第二次保存返回 false | 报错，调用 rollback，不初始化 Redis |
| 第一次保存抛异常 | 原异常向上传递，不执行第二次保存，调用 rollback |
| 第二次保存抛异常 | 原异常向上传递，调用 rollback，不初始化 Redis |
| 提交后 Redis 初始化返回 false | 报“库存初始化未完成”，数据库 commit 已调用，不调用 rollback |
| 提交后 Redis 初始化抛异常 | 原异常向上传递，数据库 commit 已调用，不调用 rollback |
| 初始库存为负数 | 写库前拒绝，不调用任何保存或初始化操作 |
| 初始库存为空 | 写库前拒绝，不调用任何保存或初始化操作 |

这些测试验证事务控制逻辑和调用顺序，没有执行真实 MySQL SQL，不能替代 MySQL 持久化与回滚联调。

### 真实 Redis 初始化（新增 6 项）

调用真实的 initializeStock，通过 StringRedisTemplate 连接自动启动的独立 Redis 3.2.100，未连接开发 Redis。

| 场景 | 验证结果 |
| --- | --- |
| 首次初始化库存 5 | 返回 true，库存字符串为 5，不创建购买记录 |
| 初始化库存 0 | 返回 true，预扣返回库存不足 |
| 初始化负库存 | 抛参数异常，不创建库存或购买记录 |
| 库存 5 已被扣到 4，再尝试初始化为 10 | 返回 false，库存仍为 4，购买记录保留 |
| 库存已售罄为 0，再尝试初始化 | 返回 false，库存仍为 0 |
| 两个客户端并发初始化 50 次，使用不同初始值 | 只有一次创建成功，49 次返回 false，保留成功创建的库存值 |

并发测试在同一测试 JVM 中使用 20 个工作线程执行 50 个调用。
