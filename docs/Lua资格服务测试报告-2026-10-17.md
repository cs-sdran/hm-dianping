# Lua 资格服务测试报告

测试日期：2026-10-17。

本次新增 13 项测试全部通过；原有订单服务的 9 项单元测试也全部通过，合计 22 项，失败、错误、跳过均为 0。没有修改业务 Java 类和 Lua 脚本。

## 测试了哪一部分

实际调用链为：`SeckillQualificationService.checkAndReserve` → `StringRedisTemplate` → 项目中的 `seckill.lua` → 真实 Redis。

测试自动启动独立 Redis，绑定本机随机端口，关闭持久化。两个独立 Redis 客户端共享这一个测试 Redis，测试结束后清理测试键并停止该进程。没有连接开发 Redis，没有访问 MySQL。

并发测试在同一个测试 JVM 中运行，使用 20 个工作线程执行 50 个请求。这验证了当前脚本在这些场景下的结果，不代表完整秒杀接口、数据库落单、跨应用进程或故障恢复已经通过验收。

## 测试结果

| 场景 | 实际通过的断言 |
| --- | --- |
| 首次购买，初始库存 5 | 返回 0，库存变为 4，集合记录用户 |
| 同一用户通过另一个 Redis 客户端重复购买 | 返回 2，库存仍为 4，集合只有 1 人 |
| 库存键未初始化 | 返回 5，不创建库存或购买记录键 |
| 库存为 `abc` 或空字符串（2 项） | 返回 5，库存值保持原样，不记录用户 |
| 库存为 0 或 -1（2 项） | 返回 1，库存不变，不记录用户 |
| 两个不同用户购买同一张券 | 均返回 0，扣减两份库存，记录两人 |
| 同一用户购买不同券 | 两张券分别成功，各扣减一份库存 |
| 用户 ID 为 9007199254740993 | 集合保存完整字符串，重复请求被识别 |
| 已购买用户在库存耗尽后重试 | 返回 1，库存和购买记录不变 |
| 同一用户并发请求 50 次，初始库存 5 | 1 次返回 0、49 次返回 2；库存 4，记录 1 人 |
| 50 个不同用户并发抢 10 份库存 | 10 次返回 0、40 次返回 1；库存 0，记录 10 人 |

库存耗尽后的重复请求返回 1，是因为当前脚本先判断库存，再判断是否买过。这与当前代码顺序一致。

非法库存测试覆盖非数字字符串和空字符串，没有覆盖所有格式异常，例如小数库存。

## 自己重新运行

在 IDEA 中打开 `src/test/java/com/hmdp/service/impl/SeckillQualificationServiceRedisTest.java`，点击测试类旁边的绿色运行按钮。测试会自行启动和停止 Redis，不需要手动往开发 Redis 写入数据。

本机默认使用 `D:/Redis/Redis-x64-3.2.100/redis-server.exe`。换电脑时，可以通过环境变量 `REDIS_SERVER` 指定 Redis 服务端可执行文件的完整路径，或将 `redis-server` 放入 PATH。

## 当前结论

当前 Java 调用 Lua、库存预扣和购买资格记录在上述测试场景中工作正常。返回 0 表示 Redis 预扣成功；它本身不会在 MySQL 创建订单。后续仍需设计并实现预扣成功后的订单处理，以及处理失败时如何恢复资格和库存。
