# 优惠券秒杀同步版验收报告

验收日期：2026-10-16（Asia/Shanghai）。结论：本轮要求的边界修正、数据库唯一约束、重复请求/并发/事务回滚/双实例验证及最终对账均已完成。

## 1. 实际修改

- `VoucherOrderServiceImpl`：同一次请求使用一个当前时间；采用 `[开始时间, 结束时间)`，到达结束时间即拒绝；库存小于等于零即拒绝；未获得锁返回“请勿重复提交”。
- 在事务服务调用之外处理重复键异常，确认同用户同券已有订单后才转换成“已经购买过”；其他主键碰撞继续抛出，避免误报。
- `VoucherOrderTxService`：保留条件扣库存、保存失败抛异常、事务回滚；查重改为统计数量；订单号按字符串返回。
- 两处秒杀查重使用普通字段条件。实测发现本机 JDK 17 与现有 MyBatis-Plus 3.4.3 的 Lambda 反射不兼容，普通字段条件保持原有查询含义，并避免本模块需要额外 JVM 开放模块参数。
- `RedissonConfig`：读取 Spring Redis 的 host、port、database、password、SSL 配置；应用关闭时调用 shutdown。这样 RedisTemplate 和 Redisson 不会各自使用不同的连接设置。
- 为结束时间精确相等的测试提供可固定的 Clock；业务默认仍使用系统时区。

核心顺序仍为：获取 Redis 锁 → 调用独立 Spring 事务服务 → 查重/扣库存/建单 → 提交或回滚事务 → finally 释放锁。

## 4. 验收结果

### 单元测试

`VoucherOrderServiceTest`：9 项，通过 9 项，失败 0，错误 0。

覆盖：不存在的券、未开始、恰好到结束时间、已结束、零库存、负库存、拿锁失败不调用事务且不解锁、恰好到开始时间可以下单且事务返回后才解锁、事务异常仍解锁。

### 真实 HTTP/MySQL/Redis 验收

| 场景 | 实际结果 |
|---|---|
| 活动未开始、已结束 | 拒绝，库存和订单不变 |
| 零库存、不存在的券 | 拒绝，不创建订单 |
| 未登录请求 | HTTP 401，不扣库存 |
| 同用户先后向两个实例购买同券 | 最终 1 单，库存 5 → 4 |
| 另一个用户购买同券 | 可以成功，总订单 2，库存剩 3 |
| 绕过接口，直接插入同用户同券的另一订单 | MySQL 1062 拒绝，记录数不变 |
| 同一用户 50 个并发请求，分发到两个 JVM | 成功 1 次、订单 1 张，库存 5 → 4 |
| 50 个不同用户并发抢 10 份库存，分发到两个 JVM | 成功 10 次、订单 10 张，库存剩 0 |
| JVM A 持有 Redis 锁且尚未建单，JVM B 收到相同购买请求 | JVM B 返回“请勿重复提交”，最终只产生 1 单 |
| 条件扣库存后，数据库拒绝插入订单 | 整个事务回滚，库存仍为 5，订单为 0 |
| 移除故障后，同一用户通过另一个 JVM 重试 | 成功，库存剩 4，订单 1 张，证明失败流程已释放锁 |

跨 JVM 排斥测试通过暂时持有测试库存行的数据库锁，使实例 A 的事务等待；此时确认 Redis 锁存在，再向实例 B 发送同用户同券请求。它验证的是 A 尚未创建订单时 B 就被 Redis 锁挡住。

插入故障通过仅存在于验证数据库的临时触发器注入，测试后已删除，业务代码中未保留故障开关。
