# 附近商户 GEO

## 接口

`GET /shop/of/type`

| 参数 | 说明 |
| --- | --- |
| typeId | 必填，商铺类型，大于 0 |
| current | 页码，默认 1，每页 5 条 |
| x | 用户经度，和 y 一起传入 |
| y | 用户纬度，和 x 一起传入 |

示例：

```text
GET /shop/of/type?typeId=1&current=1&x=120.149192&y=30.316078
GET /shop/of/type?typeId=1&current=2&x=120.149192&y=30.316078
GET /shop/of/type?typeId=1&current=1
```

提供经纬度时，查询 5 千米范围内的同类型店铺，按距离从近到远分页返回，`distance` 单位为米。经度取值 -180 到 180，纬度取值 -85.05112878 到 85.05112878。

不提供经纬度时，保留原有数据库按类型分页查询。仅提供一个坐标、无效坐标或无效页码会返回失败。

## 索引初始化和更新

- Redis key 为 `shop:geo:类型ID`，成员为店铺 ID，保存店铺的经纬度。
- 首次附近查询时，自动从数据库导入该类型全部有效坐标的店铺。
- 新增店铺成功后，使该类型索引失效；下次查询完整重建，保留其他已有店铺。
- 更新店铺成功后，使旧、新类型索引失效，并删除原有详情缓存。
- 直接执行 SQL 更新店铺不会触发应用的失效逻辑，需要同步处理相关 GEO key。
- 数据库更新和 Redis 失效是两个独立操作；当前为课程实现，未增加故障补偿及并发重建的一致性机制。

使用兼容 Redis 3.2 的 `GEORADIUS`。主要代码位于 `ShopController`、`IShopService` 和 `ShopServiceImpl`。
